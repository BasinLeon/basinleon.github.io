How a signal becomes a decision.

The system, step by step.

One worked walkthrough, so the judgment is inspectable rather than described. The account in this walkthrough is a synthetic example, written for this page. The decision rules are the ones I run; no real account record is shown, because real records would expose private material.

Step 1

Account signal

Input
Public signals: a leadership change, a funding event, a job post naming a problem, a technology already installed. In the synthetic example, a regional bank posts a security role that mentions a privileged-access modernization project.
Decision rule
A signal counts only when it names a problem the system actually solves. Activity is not a signal.
Output
The account enters the watch list with the signal and its date logged, so the reason for contact is never reconstructed later.
If missing
No signal, no outreach. The account stays in a quarterly review instead of being worked on hope.

Step 2

Qualification

Input
Firmographics, the installed stack, geography, and the signal from step 1.
Decision rule
Fit is checked against the ICP before any effort is spent, and disqualification is fast and final for the cycle.
Output
A qualified account with one named hypothesis: the problem, the likely owner, and why now.
If missing
An account that cannot be qualified is parked with a re-check date. It is never forced through.

Step 3

Enrichment

Input
The qualified account and its hypothesis.
Decision rule
People and contact data are verified against two sources before anything is written. A guessed address is worse than none.
Output
Named contacts with roles, verified routes, and the context a first message can honestly use.
If missing
Unverified contacts are flagged in the record, not emailed. The gap is visible instead of buried.

Step 4

Scoring

Input
Signal strength, ICP fit, and timing.
Decision rule
The score decides the order of work, not the volume of it. The top of the queue gets same-day attention; the rest waits its turn.
Output
A ranked daily queue a person can actually finish.
If missing
An unscored account does not jump the queue because someone asked loudly.

Step 5

Routing

Input
The score and the ownership rules for the territory.
Decision rule
Every account has one named owner and one next action. There is no shared maybe.
Output
A CRM record with an owner, an action, and a date.
If missing
Routing gaps surface in the weekly review, in the open, instead of living in someone's memory.

Step 6

Human review

Input
The drafted first touch: the message, the sequence, the reason for contact.
Decision rule
A person reads every first touch before it leaves. Agents draft; the operator decides.
Output
Approved, edited, or killed, with the reason kept.
If missing
Nothing sends unreviewed. Ever.

Step 7

Next action

Input
The outcome of the touch: a reply, a meeting, a referral, or silence.
Decision rule
Every outcome sets the next dated step before the record closes. Silence is an outcome too, and it gets a date like any other.
Output
A pipeline that behaves like a calendar, not a hope list.
If missing
The record stays open and ages visibly until someone closes it on purpose.
